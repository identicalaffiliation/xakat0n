# Приоритизация MoSCoW: Кейс 2 «Авито Очередь»

Приоритизация списка из `requirements.md`. 26 Must / 3 Should / 6 Could — Won't уже описан в `baseline-system.md`, не дублируется здесь.

## Функциональные требования

| № | Требование | Категория |
|---|---|---|
| FR1 | Ставит в очередь, если все единицы заняты | Must |
| FR2 | Выдаёт право при освобождении места, параллельно при stock > 1 | Must |
| FR3 | Право персонально и одноразово, личность определяет сервер | Must |
| FR4 | Единое окно права, не продлевается ничем | Must |
| FR5 | Истечение продвигает следующего | Must |
| FR6 | Обход очереди невозможен | Must |
| FR7 | Понятное состояние на каждом шаге, включая границу ожидания в QUEUED | Must |
| FR8 | Корректное завершение при полной распродаже | Must |
| FR9 | Добровольный выход, повторный вход в конец | Should — усиливает UX, но истечение уже решает задачу «не блокировать товар навсегда» и без явной отмены |
| FR10 | Похожие лоты при распроданном товаре | Should — прямая рекомендация кейса как усиливающая, не обязательная функция |
| FR11 | Обычные товары не проходят через очередь | Must |
| FR12 | Единица продана только по подтверждению оплаты; истечение окна на любом шаге возвращает её в оборот | Must — кейс дословно требует, чтобы неоплаченная покупка не блокировала товар бесконечно |
| FR13 | Неудачная оплата не отбирает право, попытки внутри окна не ограничены | Must — это и есть ответ на вопрос кейса «почему пользователь останется на платформе»; без этого очередь превращается в лотерею с дополнительными шагами |
| FR14 | Слот освобождается только истечением или отказом; отмена одинакова из трёх статусов | Must — упрощает модель и делает обещание «окно ваше» проверяемым |
| FR15 | Единая точка входа через штатную кнопку покупки | Must — прямой судейский критерий «очередь органично дополняет существующий сценарий»; параллельная кнопка означала бы параллельный сценарий |
| FR16 | До клика только стабильные факты, свободные места не отдаются карточке | Must — иначе даём обещание, которое не можем сдержать: места кончаются между отрисовкой и кликом |
| FR17 | Подтверждение оплаты приходит push-уведомлением | Must — без входящего факта занятая единица зависает до конца окна без причины |

## Нефункциональные требования

| № | Требование | Категория |
|---|---|---|
| NFR1 | Атомарность | Must |
| NFR2 | Персистентность | Must |
| NFR3 | Отказоустойчивость сессии | Must |
| NFR4 | Простота развёртывания | Must |
| NFR5 | Синхронный HTTP по умолчанию | Must — это ограничение архитектуры, не функция, отсечь нельзя, можно только пересмотреть саму архитектуру |
| NFR6a | Тесты на атомарность и конкурентные гонки | Must — это и есть доказательство решённой задачи кейса |
| NFR6b | Покрытие тестами всего каталога сценариев | Should |
| NFR7 | Прозрачность решений | Must — прямой судейский критерий (README) |
| NFR8 | Отсчёт таймера не зависит от часов браузера, счётчик визуально непрерывен | Must — иначе пользователь с расхождением часов видит неверное время; а прыжок счётчика при переходе к оформлению убеждает его, что таймер перезапустился |
| NFR9 | Ограничение частоты попыток оплаты | Must — неограниченное число попыток без cooldown превращает кнопку «повторить» в способ долбить бэкенд |
| NFR10 | Честность моков | Must — заглушка на месте внешнего вызывающего, а не подмена нашей логики; иначе интеграции нет, есть её имитация |
| NFR11 | Минимальный след в смежных системах | Must — от чужих компонентов только отображение, ноль изменений в их логике |

## Could have (сверх обязательных требований)

- ИИ-подбор похожих товаров через эмбеддинги — усиливает FR10, даёт бонус судейства за интеграцию ИИ
- Live-обновление через WebSocket/SSE вместо polling — обоснование отказа в `architecture.md`
- Фоновый тикер продвижения очереди (закрывает E2) — на корректность не влияет, обе финальные проверки сверяют время напрямую
- Заморозка окна на время платёжной сессии — закрывает случай «оплата ушла за 5 секунд до конца». Безопасная версия: одна заморозка, не дольше 120 секунд, только при зарегистрированной незавершённой попытке
- Снятие заявки, если пользователь купил похожий лот, пока стоял в очереди — освобождает место тому, кто товар ещё ждёт
- Админка для настройки окна и признака дефицита у товара
