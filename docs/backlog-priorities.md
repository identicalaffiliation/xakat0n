# Приоритизация MoSCoW: Кейс 2 «Авито Очередь»

Приоритизация списка из `requirements.md`. 16 Must / 3 Should / 3 Could — Won't уже описан в `baseline-system.md`, не дублируется здесь.

## Функциональные требования

| № | Требование | Категория |
|---|---|---|
| FR1 | Ставит в очередь, если все единицы заняты | Must |
| FR2 | Выдаёт право при освобождении места, параллельно при stock > 1 | Must |
| FR3 | Право персонально и одноразово | Must |
| FR4 | Право истекает по таймеру | Must |
| FR5 | Истечение продвигает следующего | Must |
| FR6 | Обход очереди невозможен | Must |
| FR7 | Понятное состояние на каждом шаге | Must |
| FR8 | Корректное завершение при полной распродаже | Must |
| FR9 | Добровольный выход, повторный вход в конец | Should — усиливает UX, но истечение уже решает задачу «не блокировать товар навсегда» и без явной отмены |
| FR10 | Похожие лоты при распроданном товаре | Should — прямая рекомендация кейса как усиливающая, не обязательная функция |
| FR11 | Обычные товары не проходят через очередь | Must |

## Нефункциональные требования

| № | Требование | Категория |
|---|---|---|
| NFR1 | Атомарность | Must |
| NFR2 | Персистентность | Must |
| NFR3 | Отказоустойчивость сессии | Must |
| NFR4 | Простота развёртывания | Must |
| NFR5 | Синхронный HTTP по умолчанию | Must — это ограничение архитектуры, не функция, отсечь нельзя, можно только пересмотреть саму архитектуру |
| NFR6a | Тесты на атомарность и конкурентные гонки | Must — это и есть доказательство решённой задачи кейса |
| NFR6b | Покрытие тестами всего каталога сценариев | Should |
| NFR7 | Прозрачность решений | Must — прямой судейский критерий (README) |

## Could have (сверх обязательных требований)

- ИИ-подбор похожих товаров через эмбеддинги — усиливает FR10, даёт бонус судейства за интеграцию ИИ
- Live-обновление через WebSocket/SSE вместо polling — обоснование отказа в `architecture.md`
- Админка для настройки времени резервации и порога дефицита

## Won't have

Полноценная регистрация, реальное оформление заказа и оплата, списание стоков, email/push-уведомления — исключены условиями кейса, см. `baseline-system.md`.
