# Пользовательские сценарии: Кейс 2 «Авито Очередь»

## Зона ответственности

Мы отвечаем за то, кто прямо сейчас имеет право нажать «перейти к оформлению» по конкретному дефицитному товару, и до какого момента это право действует. `OFFERED` — не статус оплаты, мы её не видим и не отслеживаем. Полный контекст окружающей системы — `baseline-system.md`.

## Портрет пользователя

«Охотник за дефицитом» — пользователь Авито, который давно ждал возможность купить конкретный редкий или лимитированный товар. Готов решать быстро, но боится не успеть из-за конкуренции с другими покупателями.

## Каталог сценариев

| № | Сценарий | Триггер / условие | Поведение системы | Категория |
|---|---|---|---|---|
| A1 | Обычный товар, без очереди | Товар не помечен как дефицитный | Кнопка «Купить» сразу ведёт к оформлению (заглушке); тикет очереди не создаётся | Демо |
| A2 | Вход в очередь — есть свободное место | free_slots > 0 в момент нажатия «Купить» | Тикет сразу создаётся в статусе OFFERED | Демо |
| A3 | Вход в очередь — свободных мест нет | free_slots = 0 | Тикет создаётся в QUEUED, считается позиция в очереди | Демо |
| B1 | Успешная покупка | В статусе OFFERED пользователь нажимает «Перейти к оформлению» до истечения таймера | Тикет → COMPLETED | Демо |
| B2 | Истечение права | Время OFFERED вышло, оформление не начато | Тикет → EXPIRED; на ближайшем polling-запросе любого клиента по товару система продвигает следующий QUEUED → OFFERED | Демо |
| B3 | Несколько свободных мест сразу | Остаток товара > 1 | Столько же QUEUED-тикетов параллельно переводятся в OFFERED | Реализовать + тест |
| C1 | Товар раскуплен полностью, пока пользователь ждал | Число COMPLETED-тикетов сравнялось со stock | Все оставшиеся QUEUED-тикеты по товару разом переводятся в SOLD_OUT | Демо |
| C2 | Просмотр уже распроданного товара | Пользователь открывает страницу товара, весь сток продан | «Купить» неактивна, сразу видно «Товар распродан» + похожие лоты; встать в очередь нельзя | Реализовать + тест |
| C3 | Товар пополнили после SOLD_OUT | Продавец увеличивает stock уже после того, как часть тикетов стала SOLD_OUT | SOLD_OUT-тикеты остаются терминальными (не оживляем, не уведомляем); новые клики «Купить» от любого пользователя корректно видят свободные места | Реализовать + тест |
| D1 | Пользователь сам выходит из очереди | Нажимает «Отменить» в QUEUED или OFFERED | Тикет → CANCELLED; отмена из OFFERED сразу освобождает слот, не дожидаясь таймаута | Демо |
| D2 | Повторный вход при уже активной заявке | Снова жмёт «Купить», у него уже есть QUEUED/OFFERED тикет по этому товару | Новый тикет не создаётся — возвращается существующий | Реализовать + тест |
| D3 | Попытка обойти очередь | Прямой переход к «оформлению» без активного OFFERED-права на этот товар | Доступ блокируется | Демо |
| D4 | Попытка переиспользовать / использовать чужое право | Запрос на оформление с COMPLETED-тикетом либо с чужим user_id | Доступ блокируется | Демо |
| D5 | Двойной клик по «Купить» | Два одновременных запроса на создание тикета от одного пользователя | Та же проверка «уже есть активный тикет» — создаётся только один | Реализовать + тест |
| D6 | Повторный вход после отмены или истечения | Пользователь жмёт «Купить» снова, имея тикет в терминальном статусе (CANCELLED/EXPIRED) по этому товару | Создаётся новый тикет со свежим created_at — естественно встаёт в конец очереди (или сразу OFFERED, если есть места) | Реализовать + тест |
| E1 | Возврат после разрыва сессии | Пользователь закрыл вкладку и вернулся позже | Статус подтягивается заново по паре (item_id, user_id), не по client-side токену | Реализовать + тест |
| E2 | Никто не опрашивает статус | Все, кто мог продвинуть очередь, ушли со страницы | Продвижение зависает до следующего polling-запроса кем угодно по товару | Осознанно не в MVP — задокументированное ограничение |

## Живой демо-путь

A3 (второй и третий пользователь встают в очередь) → A2/B1 (первый получает право и покупает) → C1 (оставшиеся видят «раскуплено» + похожие лоты) — либо, если хотим показать истечение вместо мгновенной покупки: B2 (не успел) → следующий получает OFFERED → D3 (попытка обхода блокируется).

Остальные сценарии (B3, C2, D2, D5, E1) — реализуем и покрываем юнит-тестами, в демо не показываем из-за ограничения по времени.

## Состояния заявки

```
QUEUED
  |-- есть свободное место -----> OFFERED
  |-- весь сток продан ---------> SOLD_OUT
  +-- пользователь отменил -----> CANCELLED

OFFERED
  |-- успел вовремя ------------> COMPLETED
  |-- время истекло -------------> EXPIRED
  +-- пользователь отменил -----> CANCELLED
```

| Состояние | Сообщение пользователю | Следующий шаг |
|---|---|---|
| QUEUED | «Вы N-й в очереди» (N = позиция) | Ждать / выйти из очереди |
| OFFERED | «Товар зарезервирован для вас, осталось MM:SS» | Перейти к оформлению / отменить |
| EXPIRED | «Время вышло, право на покупку истекло» | Вернуться к товару / встать в очередь заново |
| SOLD_OUT | «Товар раскуплен» | Посмотреть похожие лоты |
| CANCELLED | «Вы вышли из очереди» | Вернуться к товару |
| COMPLETED | «Переход к оформлению» (заглушка) | — |

## Сделанные допущения

- Дефицитный товар — флаг `is_limited = true` и остаток ≤ порога (для демо: 1–5 шт.). Обычные товары очередь не запускает.
- Момента «создания очереди» нет: каждый клик «Купить» заново вычисляет свободное место и либо выдаёт OFFERED, либо ставит в QUEUED. При остатке > 1 несколько пользователей получают право параллельно.
- Идентификация пользователя упрощена, без полноценной авторизации, но достаточна, чтобы связывать заявки с конкретным пользователем.
- «Переход к оформлению» в демо — заглушка. Ответственность заканчивается на COMPLETED.
- Время действия права — конфигурируемо: 5–10 минут для «продакшена», 30–60 сек для демо.
- Правило очереди — простое FIFO по времени присоединения.
- Один пользователь держит только один активный (QUEUED/OFFERED) тикет на товар; на разные товары — без ограничений.
- Терминальные статусы (CANCELLED, EXPIRED, SOLD_OUT) не оживляются автоматически — ни при повторном интересе пользователя, ни при пополнении стока. Обратный путь только один — новый клик «Купить», создающий новый тикет в конце очереди (D6).
